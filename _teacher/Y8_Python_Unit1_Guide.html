Getting started with Python Unit 1

How the online lessons work, the password you need to skip a task, and what the coloured progress bar is telling you.

1The lessons

Each lesson is one interactive page. Students work through it in the browser. No installs or logins are needed, and Python runs inside the page.

Students see one question at a time. After a correct answer the page moves on by itself, and Back/Forward buttons let them revisit earlier questions. In Investigate and Modify each step builds on the last one, so students never retype earlier work.

2Running a lesson

  1. Give students the link. They can open it from the hub (index.html → Year 8 → Python Unit 1) or you can post the lesson's link directly.
  2. Leave them on Predict first. The stage tabs along the top can be clicked, but the learning depends on predicting before running. Discourage jumping ahead.
  3. Work is saved automatically in the browser. If a student closes the tab and comes back on the same computer and browser, they carry on where they left off. Their work does not follow them to a different computer.
  4. Errors come with help. When their code fails, a 💡 Get help button appears. It explains the error in plain English and suggests one fix. It never opens by itself, so students read the real Python error first.
  5. Reset without losing work. ↺ Reset to original in Investigate and Modify puts the code back to how it was at the start of the current step. Earlier steps are kept.
Google Classroom (optional): to have scores sync as draft grades and each student's work attached to their submission, run the Classroom setup page once on your teacher account, then post the lesson as a Classroom assignment. Without it, the lessons work exactly the same but scores stay on the student's screen.

3Skipping a task (teacher password)

If a student fails the check on the same Investigate step or Modify task 3 times, a “Skip this step →” or “Skip this task →” button appears. Students can't skip by themselves. The button opens a password box for you to fill in.

Teacher password (same in every lesson)
outwood
Type it into the box and press Skip or Enter. It is not case-sensitive.

What happens when you skip

  • The student moves on to the next step with their code carried forward. In the bug-fixing step the planted broken line is removed first.
  • The stage tab is marked as skipped, and the progress bar at the top turns red (see below).
  • A skipped Modify task scores nothing. The student can go Back and try it again, and if they pass it later the red disappears.
Before skipping, it's worth one conversation first. Most students who are stuck have a small typo or haven't clicked 💡 Get help yet.

4Reading the progress bar

The thin bar across the top of the page is designed to be read from the front of the room. Its length shows how far through the five PRIMM stages the student is (20% per stage). Its colour tells you who needs you:

Shimmering purple → tealOn track
Pulsing amberPossibly stuck: go and check
Solid redSomething was skipped

Amber = no progress for a while

It turns amber when a student has stayed on the same stage for:

  • 8 minutes on Predict, Run or Investigate
  • 10 minutes on Modify
  • Never on Make, because open-ended building time is expected there

It clears as soon as they move to another stage.

Red = skipped work still unresolved

The bar flashes red when you skip a step, then stays red while any skipped step hasn't been passed. When the student goes back and passes it, the normal colours return.

Red takes priority over amber, so at a glance it tells you that student needs follow-up (for example, DIRT time).

The score badge (bottom-left)

Score: 45% 🟩 85% — Go for Gold! ⭐ ⭐ 100% — Gold!

Separate from the bar, this is the student's score. Predict, Run and Investigate are worth 5% each, each Modify task 10%, the Make program 25%, and the Make extension about 20%, capped at 100%. Grey is under 80%, green is 80% and above, and gold is 100%. This is the score sent to Google Classroom if it's set up.
