Analysis of Year 11 Activity Types

This report provides an overview of the interactive learning activities provided for Year 11 Computer Science (J277) students, including a frequency analysis of task types and recommendations for future development. Based on 18 HTML activity files across all Y11 topic folders.

Detailed Breakdown of Types

1. Fill in the Blanks (Gap Fill)

The most versatile type, appearing in three main variants:

  • Drag and Drop: Used for terminology and legislation facts.
  • Dropdown Selection: Used for complex sentences where technical precision is required.
  • Click-to-Place: A streamlined variant used in Cybersecurity and Impacts.

2. Pseudocode Verification

A core part of the Paper 2 preparation. Five dedicated activities use a custom pseudocode-transpiler.js to run OCR-standard pseudocode and verify it against hidden test cases, providing instant mark-scheme style feedback. Topics covered: standard algorithms, functions/procedures, and file handling.

3. Scenario Classification

Highly effective for Paper 1 (Social, Ethical, Legal). Students sort scenarios into categories like "Ethical Issue" or "Malware Type". Most use a visual drag-and-drop interface with instant red/green feedback.

4. Interactive Visualisers

Canvas or SVG-based tools that let students manipulate a representation and see the effect. Current examples include the Sound wave visualiser (frequency/amplitude sliders), the Images pixel-colour grid, and the Binary/Hex conversion tool. Good for "seeing" concepts rather than just reading them.

5. Canvas Builders

Open-ended drag-and-drop canvases where students construct something (a network diagram, a mind map). Higher cognitive load than classification tasks — students must recall structure, not just recognise it. Currently used for Network Topology and OS Mind Map.

Suggestions for New Activity Types

Items marked NEW are additions beyond the original list. Items without that tag were in the original suggestions and are not yet built.

  • Parson's Problems A variation of coding challenges where students drag pre-written lines of pseudocode/code into the correct order. Focuses on logic and structure without syntax frustration — lower barrier than blank-canvas coding but still requires understanding of sequencing and control flow.
  • Interactive Trace Tables A grid where students fill in variable values step-by-step as an algorithm executes. Directly maps to the trace table question style in Paper 2. Each cell checked individually with instant feedback; students can request a "hint" that reveals the next row.
  • Hotspot / Label-the-Diagram An image-based activity where students drag labels onto a diagram (e.g., parts of the CPU, inside a hard drive, OSI layers). Works well for hardware and networks topics where spatial understanding matters.
  • "Pick the Odd One Out" A rapid-fire game where students identify which of 4 terms doesn't belong (e.g., three input devices and one output device) and must select the correct reason why. Very quick to play; builds category fluency without being another standard MCQ.
  • Timed Flashcard Recall A high-pressure recall mode where students must type the definition of a keyword before a timer runs out. Useful for building fluency in key terms. Tracks which cards were answered correctly and surfaces harder ones more often (spaced-repetition lite).
  • SQL Query Builder A visual tool for constructing SELECT, FROM, and WHERE clauses from blocks against a mock database table. Shows the result set updating live so students see why each clause matters.
  • "Fix the Bug" (Visual) A working algorithm is shown with 1–3 deliberate bugs. Students click the offending line and select the correct replacement from a short list. Easier than writing from scratch but still requires reading and understanding code — good for the "identify the error" exam question type.
  • Exam-Style Scenario Chain NEW A single scenario (e.g., a business that suffers a ransomware attack) followed by 3–4 linked questions of increasing mark value: identify → explain → evaluate. Mirrors the structure of a real J277 paper question set so students practise reading context across multiple sub-questions, not just isolated MCQs.
  • Spot the Difference (Two Code Blocks) NEW Two side-by-side pseudocode listings are shown; one has 2–3 changes. Students must identify each changed line and explain whether the change improves, breaks, or has no effect on the algorithm. Develops close reading skills and prepares for the "what would happen if…" exam questions.
  • Keyword Crossword NEW A compact crossword (8–12 clues) generated from topic keywords and their definitions. Clues can be "definition → word" or "word → definition". Breaks up the monotony of flashcard-style revision; the crossing letters provide retrieval cues without giving the answer away.
  • Algorithm Dry-Run Animator NEW A step-through tool for standard algorithms (bubble sort, binary search, linear search). Students press "Next Step" and must predict what changes before the animation reveals it. Scaffolds the trace-table skill and makes the algorithm's mechanics visible. Could be paired with a fill-in trace table so students commit a prediction first.
  • Number System Bit-Flipper NEW An interactive 8-bit register where students toggle individual bits and immediately see the denary, hex, and two's complement equivalents update. Includes tasks like "set this register to 127" or "flip one bit to cause an overflow." Extends the existing Binary/Hex activity with hands-on manipulation rather than typed answers.
  • Colour-Code the Exam Answer NEW A sample student exam answer is shown. Students highlight phrases and tag them as "point", "example", or "missing". A model answer is then revealed and compared. Builds awareness of what makes a full-mark answer — useful for 4- and 6-mark questions where students commonly under-explain.
  • Logic Gate Truth Table Builder NEW Students are shown a logic circuit diagram (AND/OR/NOT/NAND/NOR/XOR) and must complete its truth table row by row. Each row is checked individually. A harder variant asks students to identify which gate type produces a given truth table. Maps directly to the Boolean logic section of the J277 specification.
  • Protocol Stack "Packet Journey" NEW An animated visualisation of a packet moving through the TCP/IP stack (Application → Transport → Internet → Link). At each layer students must answer what is added (header type, purpose) before the packet continues. Combines the sequence-sort and classification skills in a narrative context.
