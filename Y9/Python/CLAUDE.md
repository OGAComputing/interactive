# Station Zero story layer (Y9 Python)

Read this before building or changing a Y9 Python lesson or `_templates/PRIMM_Python_Y9_StationZero.html`.

## Y9 Station Zero template (`_templates/PRIMM_Python_Y9_StationZero.html`)

This is the Y9 PRIMM template with a survival-horror story layer for the Y9 Python unit (see the "Narrative thread" section of `Knowledge Base/project_y9_python_mtp.md`). Everything else is identical PRIMM markup and JS. It differs in five places:

- a darker "hull" palette, using the same token names
- a station header with the objective, the crew readout and a **Light mode** switch (`theme-toggle.js`, in `.sz-header-right[data-theme-toggle-slot]`). It replaced the old Station map button, which students rarely used
- a situation-report overlay (an opening still with the story typed over it, then the map and status readouts) that shows once each: on first load, after each stage's first completion, and when Make first passes. It is styled as an 80s green-phosphor terminal whose text types itself in with a blinking block cursor. The still and the story can't be skipped: until the story has typed in (`lockReport` / `unlockReport`), clicks and keys don't skip, Continue (greyed out, `aria-disabled`) and Escape don't close, and the report doesn't scroll. After that, a click or key shows the rest (live feed, map, readouts) at once. `LOCK_MAX_MS` (10 s) frees it if a still never loads. Reduced motion and map re-opens show it all at once, unlocked. The story comes first, over the opening still (see **Opening stills** below). There is no close button: the only way out is **Continue**, at the foot under the live feed and the map (Escape also closes it, for keyboard users). The template also carries collapsible "Remind me" cards (`<details class="remind">`) for worked reminders
- a self-contained story `<script>` whose only per-lesson edit is the `STORY` object (FILL IN Ⓢ)
- three hooks in the module, marked `STATION ZERO hook`: `start()`, `beat(stage)` and `showMap()`, each called as `window.StationZero?.…` (`showMap()` re-opens the latest report; nothing in the page calls it now)

**Live feed (trial):** a beat can have an `impact` entry. When the stage is completed, a short animation plays under the story, once the story has typed in and the feed has been scrolled into view: the output of the stage's final action travels down a wire into a station device, which reacts. Each lesson draws its own devices (Wake Up: the door, the pod records, the crew locator; Life Support: the O2 recycler, the life-support logs, the corridor lights, the motion tracker) in its story script's `SCENES`, and each scene is chosen by `impact.scene`. The module passes that output as `beat(stage, { feed })`. It doesn't replay on map re-opens; a click shows the final frame, and so does reduced motion.

**Story choices:** Modification 1 is a "Your call" card (`#m1_choice`, radios `m1_choice`). The student picks an option, and only then does that option's requirement appear (`CHOICE` in the module fills `#req_m1_1_text`). Both options pass: `evalMod(key, raw, out, choice)` takes the choice. When Modification 1 passes, the choice locks and goes to the story layer as `StationZero.choose(key, value)`, which stores it for the whole unit in localStorage `sz_choices`. Its consequence plays straight away: the `M1` report opens as soon as Modification 1 passes (not at the end of Modify), and its button reads **Onwards to Modification 2 →**. So write the `M1` beat about Modification 1's output only. If Modification 1 was skipped, the report plays at the end of Modify instead. A beat can then have `variant: choices => name` plus `variants: { name: {…beat fields} }`.

From Lesson 2 (and in Wake Up), a PRIMM cycle has a **crisis** before these: a "Your call" card at the top of Investigate step 1 (`#i_choice`, radios `i_choice`) with no code. The step's task (`#i1_task`) appears once it's picked, step 1 won't pass without it, and it locks when step 1 passes or is skipped. Then `StationZero.choose('shield', …)` runs and a short `I1` report plays (`ORDER` includes `'I1'`). The crew member it puts in danger stays on every later report as a falling heart-rate readout. Built in Proximity, in Wake Up (`voice`: answer Hale's voice on the intercom or stay silent; it puts nobody in danger, so it has no stake readout and only changes the wording of the door choice and the reports), in Locked In (`heat`: keep the Cryo Bay warm, which leaves you `hunted` and maybe `injured`, or fast-cycle the airlock, which freezes the bay; the seals call settles either), and in the template (`CRISIS` in the module, an example `I1` beat, and the "you" crew states `hunted` / `injured` for crises that put the student at risk). Delete the template's `#i_choice` card in a chapter with no crisis.

Every PRIMM cycle has **two** choices. The second is a "Your call" card on **Make** (`#m2_choice`, radios `m2_choice`). It reacts to the first: a `#m2_choice_report` line repeats the fact from the last report that decides the better call, and picking it recovers a bad first choice. The chosen option adds one fixed `print` line at the end of the Make program, checked as the last `MAKE_CHECK` req by `evalMake(raw, out, choice)`. It locks when Make first passes, and `StationZero.choose()` runs just before `beat('M2')`, so the cliffhanger settles both choices. `StationZero.choices()` returns a copy of every choice so far. The crew roster, the outcome tiers and the L2–L7 plan are in the MTP's "Choices and the crew count" section. The template has the story-layer side (`choose`, variants, Drive sync, recap) but not the "Your call" cards yet.

**Choices on another computer:** `choose()` also saves the choices to the student's Google Drive with `Classroom.submitResults(choices, 'Station Zero')` (one file, "Station Zero — Results", shared by every chapter). `start()` reads it back with `fetchResults` and merges it with localStorage: each choice carries a timestamp in `sz_choices._at`, and the most recent wins. It waits up to 4 s for Drive before the first report. This only works for students signed in through a Classroom link; otherwise each `variant()` uses its default. Students own the Drive file and could edit or delete it, so values are cleaned on read (lower-case letters, digits and `_`, as in `pod5`), and an edited value can only change their own story. A report counts as seen when it's closed, not when it opens, so one cut off by a reload or the sign-in redirect shows again.

**Crew readout:** the header has a **Crew** button between the objective and the light-mode switch. It shows five pod lights, a heart-monitor line and a crew count such as `4/5`. Hovering over it, clicking it, or tabbing to it and pressing Enter opens a crew manifest with an ID-badge portrait, a heart line and a status for each crew member. Each light state has its own shape: alive is a solid square, at risk is amber, critical blinks amber, dead is a hollow square with a cross, you is a ring, and unknown is a dashed outline. The roster (`CREW`: names, pods, roles, portraits) is shared by every chapter, like `ROOMS`. The portraits are cropped from generated images in `_drafts/crew/` and inlined in `FACES` as 200×240 WebP data URIs (~6 KB each), and CSS tints them phosphor green. "You" is a faceless silhouette, because it's the student. A seventh state, **compromised** (a red diamond light, "Tag active", a "NOT HUMAN" bar, an upside-down slow heart line), swaps in the face `FACES[face + '_x']` in cold grey with a glitch every few seconds, and isn't counted as alive. Hale becomes compromised when Wake Up's cliffhanger (M2) closes, and stays so in Life Support and every later chapter (the template's `crew` starts from `{ 2: 'compromised' }`). The only per-lesson edit is `STORY.crew(choices, seen)`: it returns `null` while the crew is unknown, or `{ pod: status }` for the pods that differ from the start of the story (Hale dead, everyone else stable). It is re-read only when a report closes, so gate each change on the report that reveals it, and the readout never gets ahead of the story. In Wake Up, the crew is unknown until the pod records load (I). Life Support is an optional round that can only help: if Wake Up left Patel critical, Make's `transfer: pod5` saves him (Proximity reads that one choice), and otherwise he stays critical. Nobody dies in it. In Proximity, the crisis decides which of Chen and Patel is critical, and the lockdown and power calls decide whether they're saved. Reduced motion draws the heart lines as still traces.

**Opening stills:** every beat has `cam`, a key of the story script's `CAMS` (`{ label, alt, src }`): a generated picture of the scene. The report opens on it, full width and framed as a camera feed (label, blinking REC, scanlines). It holds at full brightness for 2.6 s (`STILL_MS`), dims, and then the headline, recap and story type in over it in green. This was added because students skipped reports that all looked alike. The hold is played frame by frame (`startStill`), counting at most 50 ms a frame, because the first report opens while Python is still loading and a CSS timeline would run on through that stall. Map re-opens, reduced motion and a click or key show the dimmed final frame. A variant can swap in its own `cam`. An entry whose picture isn't made yet has `src: ''`: the story then types straight away on a dark screen. To add a picture, save it in `_drafts/story/` and run `python _drafts/story/add_still.py <page> <key> <image>`, which crops it to 16:9, makes a 960×540 WebP (≤ ~70 KB) and fills that key's `src`. The image prompts for every beat are in `_drafts/story/PROMPTS.md`. The `/story-stills <page>` skill (`.claude/skills/story-stills/`) makes the missing ones with Gemini in Chrome and runs `add_still.py` for each. To see which beats still need a picture, search the page's `CAMS` for `src: ''`. Hale's whole L1 story (his last log, the tag reveal) is in Wake Up, and Life Support's recap retells it. The template has the slot but an empty `CAMS`. Stills for later chapters (the L5 drone feed, the breach, the two endings) are waiting in `_drafts/story/`.

**"Previously…" recap:** a chapter's intro beat can have `previously`: an array of one or two short bullets (one sentence each) recapping the chapters before it, shown under the headline. Keep them short, because students don't read long recaps. Put it in the variants so it follows the student's choices. It's there for students who missed a lesson (Life Support has one; Wake Up opens the story, so it doesn't).

**Light mode ("day shift"):** the light palette is a `LIGHT MODE` block at the end of each page's `<style>`, under `html[data-theme="light"]`. The work area goes light (white cards, `#0f172a` ink, deeper teal `#0f6b63` accent; every text pair ≥ 4.5:1, most ≥ 7:1, and input borders 3:1). The station's own screens stay dark in both modes, because they are screens: the header console, the crew manifest, the situation report and map, the camera stills and the chapter-done banner. The block also re-tints `code-editor.js`'s purple light editor to slate, with `.code-checker`-prefixed selectors so they beat the editor's own (injected later). Each chapter keeps its tint in `--canvas` (Wake Up slate, Life Support green, Proximity blue, Locked In red). The switch is drawn as a console key: phosphor on black when off, lit green when on.

The overlay is a fixed div at z-index 9000, not a `<dialog>`, so it never covers classroom.js's sign-in overlays. `?story=off` stops reports appearing automatically. The station layout (`ROOMS`) is shared by every chapter, so don't change it per lesson.
